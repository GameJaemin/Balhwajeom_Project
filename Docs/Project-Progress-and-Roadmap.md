> 기준일: 2026-09-09  
> 문서 목적: 흩어진 설계·인수인계 문서를 하나의 실행 기준으로 통합한다.  
> 현재 단계: **조사 게임플레이의 최종 프로토타입 완료 → 본편 통합 및 제작 단계 진입**

## 1. 한눈에 보는 현재 상태

프로젝트의 핵심 조사 루프는 현재 프로토타입 레벨에서 끝까지 동작하는 상태다.

```text
증거 오브젝트 접근
→ 거리 라벨과 관찰 정보 확인
→ F 조사 또는 카메라 촬영
→ 키워드·사진 획득
→ 태블릿 인물 폴더에서 사진 문장 완성
→ 완성 사진과 키워드로 진술 반증
```

다만 이것은 **샘플 데이터와 전용 프로토타입 레벨을 기준으로 한 기능 완성**이다. 프로젝트 전체가 출시 가능한 상태라는 뜻은 아니다. 다음 단계의 중심은 새 시스템 개발보다 본편 시나리오 데이터 입력, 메인 레벨 통합, 전체 진행 저장, 연출 보강, 패키지 환경 검증이다.

## 2. 현재 시스템 구조

### 2.1 데이터와 런타임의 경계

```text
Scripts/Investigation/*.csv
          ↓ 재임포트
8개 Investigation DataTable
          ↓ Project Settings 연결
UBalhwajeomInvestigationSubsystem
 ├─ 증거 인스턴스 상태
 ├─ 획득 키워드
 ├─ 촬영 사진
 ├─ 키워드 문서 선택 상태
 └─ 문장 풀이 상태
          ↓
EvidenceActor / Camera / Tablet / Messenger
```

- DataTable은 플레이 중 바뀌지 않는 기획 정의 데이터다.
- 플레이 중 바뀌는 값은 InvestigationSubsystem이 소유한다.
- Row Name과 행 내부 ID는 반드시 같아야 한다.
- 카메라, 증거 액터, 태블릿은 각자 촬영·획득 상태를 따로 저장하지 않고 Subsystem을 단일 기준으로 사용한다.

### 2.2 현재 사용 중인 조사 DataTable 8종

| DataTable | 역할 |
|---|---|
| `DT_EvidenceDefinitions` | 증거 오브젝트와 최초 상태 |
| `DT_EvidenceStates` | 상태별 상호작용·거리 문구·촬영 조건 |
| `DT_Words` | 키워드 정의와 인물 폴더 소속 |
| `DT_Photos` | 사진, 인물, 분석 문장, 지급 키워드, 스토리 정보 |
| `DT_KeywordDocuments` | F 조사 문서 본문 |
| `DT_KeywordChoices` | 문서별 선택지와 지급 키워드 |
| `DT_Sentences` | 사진 분석 문장과 진술서 반증 조건 |
| `DT_Characters` | 태블릿 인물 폴더 이름과 정렬 순서 |

`DT_OutputTexts.uasset`은 최신 구조에서 참조되지 않는 테이블로 확인되어 저장소에서 제거했다(2026-09-09).

### 2.3 기능별 연결 구조

#### 증거 상호작용

`ABalhwajeomEvidenceActor`가 배치 인스턴스 ID, ObjectID, CurrentStateID를 들고 Subsystem에 등록된다. 거리 라벨과 F 상호작용은 현재 EvidenceStateDefinition을 기준으로 갱신된다. `Once`, `Repeatable`, `ChangeState`, 단순 텍스트, 키워드 선택 창이 공통 흐름으로 연결되어 있다.

#### 카메라와 사진

카메라는 현재 증거 상태의 `bCanCapture`, `PhotoID`, 초점 거리 조건을 읽는다. 유효한 신규 촬영만 PNG로 저장하고 `FCapturedPhotoRecord`를 등록한다. 같은 PhotoID는 중복 촬영할 수 없고, 사진 등록 성공 시 `GrantedWordIDs`의 키워드를 한 번만 지급한다.

#### 태블릿과 추리

태블릿은 CharacterID를 기준으로 인물 폴더를 만들고, 해당 인물의 사진·키워드·진술서를 조회한다. 사진 분석은 정답 슬롯이 채워지면 자동 판정하며, 해결된 추리 사진만 진술서 증거 후보가 된다. 진술서는 키워드와 완성 사진을 조합해 반증한다.

#### 메신저

메신저 방과 메시지는 Data Asset으로 관리된다. 날짜 변경 지점에 구분선이 표시되며 메시지 키워드는 InvestigationSubsystem의 획득 상태와 연결된다. 기존 예시 날짜는 임시 데이터이므로 본편 연표에 맞게 교체해야 한다.

#### 스토리 상태

Gameplay Tag 기반 `StoryStateSubsystem`과 자동 테스트가 존재한다. 조사 프로토타입과 별개 기반은 마련됐지만, 본편의 챕터 진행·분기·저장 정책과의 최종 통합은 별도 완료 기록이 없다.

## 3. 지금까지의 진행 구조

### 1단계 — 협업 기준과 기본 시스템

- Unreal 프로젝트 폴더·에셋 명명·Git LFS·개인 테스트 영역 규칙 정리
- 카메라, 상호작용, 태블릿, 메신저의 초기 기능 구현
- Gameplay Tag 기반 스토리 상태 기반 구현

### 2단계 — 3인 병렬 개발 구조 확정

```text
담당자 1: 데이터 구조·Settings·InvestigationSubsystem
담당자 2: EvidenceActor·거리 표시·F 상호작용
담당자 3: 카메라·사진 저장·HUD
                         ↓
                      통합
```

바이너리 에셋 충돌을 피하기 위해 Investigation 공통 코드, EvidenceActor, 카메라 코드의 담당 경계를 나눴다.

### 3단계 — Investigation 공통 기반 구현

- 정적 정의와 런타임 상태 분리
- DataTable 설정·로드·ID 교차 검증
- 증거 등록, 상태 전환, 키워드 획득, 사진 등록, 문장 판정 API 구현
- 이벤트 기반으로 EvidenceActor·카메라·태블릿 연결

### 4단계 — 데이터 구조 재설계

- 인물 폴더용 `DT_Characters` 추가
- 키워드 선택지를 `DT_KeywordChoices`로 분리
- 사진에 CharacterID와 GrantedWordIDs 연결
- 진술서에 LieText 추가
- 사용하지 않는 ResultTextID 등 제거
- 인물별 사진·문장 조회와 문장 해결 상태 조회 API 추가

### 5단계 — 카메라·사진 통합

- 기존 카메라의 자체 수집 배열을 Subsystem 기준으로 전환
- 촬영 순간 상태 재검증, PhotoID 중복 차단
- 단일 pending 캡처와 비동기 PNG 저장
- 저장 후 등록 실패 시 생성 파일 정리
- 카메라 HUD의 촬영 상태를 Subsystem 조회로 통일

### 6단계 — 최종 조사 프로토타입 완성

- 돼지 거울·스노우글로브·조사 문서·사진 문장·진술서로 이어지는 샘플 루프 제작
- 프로토타입 레벨과 테스트용 Evidence Blueprint 제작
- 태블릿 폴더, 사진 분석, 진술 반증 UI 연결
- CSV 예시와 에디터 재생성·검증 스크립트 추가
- 문서 기록 기준으로 에디터 빌드, Investigation 자동화 10개, DataTable 교차 검증, 태블릿/메신저 스모크 테스트 통과

### 7단계 — 메신저와 조사 상태 통합

- 메신저 메시지의 날짜·시간 표시와 날짜 구분선 보강
- 메신저 키워드를 InvestigationSubsystem의 획득 상태와 연결
- 태블릿·메신저 위젯과 샘플 Data Asset 갱신

### P1 — 알파 안정화 작업

#### P1-1. 전체 진행 SaveGame

현재 영속 저장은 촬영 사진 메타데이터에 한정된다. 아래 상태도 저장·복원해야 한다.

- EvidenceRuntimeStates
- AcquiredWords
- KeywordDocumentStates
- SentenceProgress
- StoryStateSubsystem의 진행 태그
- 저장 데이터 버전과 마이그레이션 정책

완료 조건: 게임 종료 후 재실행해도 증거 상태, 키워드, 사진, 풀이, 스토리 진행이 서로 모순 없이 복원된다.

#### P1-2. 사진 파일 수명주기

- SaveGame과 `Saved/Investigation/Photos`의 원자적 보존·삭제 정책
- 손상되거나 누락된 PNG 처리
- 이전 세션 폴더와 고아 이미지 정리
- `bViewedInTablet` 갱신 API 및 읽지 않음 표시 정책

완료 조건: 정상 저장·로드, 등록 실패, 강제 종료, 이미지 누락 상황에서 잘못된 갤러리 항목이나 고아 파일이 남지 않는다.

#### P1-3. 카메라 실제 실행 환경 검증

- PIE와 패키지에서 PNG 생성 확인
- 저장 이미지에 HUD·조준선·카메라 연출이 포함되지 않는지 확인
- 고해상도 PNG 압축 시 프레임 hitch 측정
- viewport screenshot 방식이 실패하면 SceneCapture 방식으로 전환

완료 조건: 목표 플랫폼의 Development 패키지에서 촬영 품질과 성능 기준을 만족한다.

#### P1-4. 레거시와 문서 정리

- Deprecated 카메라 필드·함수의 Blueprint 참조 0건 확인 후 제거
- `DT_KeywordDocuments`의 구형 중첩 선택지 필드 제거
- `Scripts/Investigation/README.md`의 “7종” 표기를 실제 8종에 맞게 수정
- 과거 설계 문서에 `역사 기록/최신 문서 아님` 상태를 명시

완료 조건: Reference Viewer와 전체 Blueprint Compile에서 구형 API 사용처가 없고, 신규 작업자는 이 문서만으로 현재 기준을 찾을 수 있다.

## 7. 마일스톤 공통 완료 기준

각 마일스톤은 다음을 만족해야 완료로 표시한다.

- C++ 에디터 빌드 성공
- 관련 자동화 테스트 성공
- 변경된 Blueprint 전체 Compile 성공
- DataTable ID와 교차 참조 검증 성공
- PIE 수동 테스트 절차와 결과 기록
- `.uasset`/`.umap` 담당자 충돌 여부 확인
- 새 임시 데이터와 하드코딩 목록 기록

최종 릴리스 후보는 추가로 다음을 만족해야 한다.

- 시작 맵부터 엔딩 또는 목표 데모 종료 지점까지 전체 플레이 가능
- 저장·종료·재실행 후 진행 상태 정상 복원
- 패키지 환경에서 촬영 PNG가 열리고 갤러리에 재표시됨
- 치명 오류, 진행 불가, 데이터 참조 오류 0건

## 8. 당장 시작할 작업 순서

1. 최신 커밋 기준으로 빌드와 전체 자동화를 다시 실행한다.
2. 본편에서 사용할 인물·증거·키워드·사진·문장 ID 마스터를 확정한다.
3. `Level_Main`에서 완성해야 할 최소 수직 슬라이스 한 개를 고른다.
4. 해당 흐름의 실제 데이터를 8개 DataTable에 넣고 메인 레벨에 배치한다.
5. 사진 외 조사·스토리 런타임 상태까지 SaveGame에 포함한다.
6. 패키지 촬영 검증과 레거시 제거를 마친 뒤 전체 콘텐츠를 확장한다.
